# AEGISAI

**Enterprise workforce intelligence platform** — models how AI reshapes a
business, connecting processes, activities, roles, and skills into one
navigable graph, then overlaying AI opportunities, deterministic impact
scoring, and skill-trend forecasting on top.

Given any process — seeded or typed in live, never seen before — the
system extracts its activities, identifies the roles that perform them
and the skills those roles need, proposes realistic AI opportunities,
scores each one on a transparent weighted formula, and wires the whole
thing into a connected graph. The same pipeline handles every input; there
is no separate "demo path."

Demonstrated on a fictional retail bank, Northstar Bank — 10 processes
across Retail Lending and Trade Finance & Compliance, generated by a real
LLM, not hand-written.

## What it actually does

- **Dynamic analysis, not a fixed dataset.** Type in any process name and
  the system runs it through a real LLM extraction → embedding-based
  deduplication → deterministic scoring → persistence pipeline, live.
  Verified repeatedly against a real Groq API, including two independent
  calls proposing the same role and skill names — the deduplication
  mechanism reused the exact same database rows instead of creating
  duplicates, with no memory between calls.
- **Deterministic scoring, not LLM opinion.** Every AI Impact Score is a
  fixed weighted formula (repetitiveness, data availability,
  predictability, digitalization, AI-capability fit). The model proposes
  the five inputs with reasoning; application code computes the score.
  The model never writes a number directly.
- **Skill-trend classification that's actually reachable.** Six
  categories (Emerging, Increasing, AI-Augmented, Changing, Declining,
  Enduring Human), computed by plurality across every AI opportunity
  linked to a skill — recomputed automatically as the graph grows, not a
  label set once by hand.
- **Evidence-backed, never fabricated.** AI opportunities are linked to a
  curated research corpus via semantic search; if nothing clears the
  relevance threshold, nothing gets attached — no invented citations.
- **A real 2D and 3D graph.** Every node is a live database row.
  Click-to-explore navigation in 2D; a full WebGL constellation view in
  3D, where AI opportunities render as actual glowing points of light.

## Architecture

```
React + TypeScript ──▶ FastAPI ──▶ Deterministic scoring / dedup / evidence
                                 └▶ LLM (Groq, Ollama fallback) + local embeddings
                                 └▶ PostgreSQL + pgvector
```

Full diagrams: [`docs/architecture/architecture-diagram.md`](docs/architecture/architecture-diagram.md).

## Stack

| Layer | Choice |
|---|---|
| Frontend | React 19, TypeScript, Tailwind CSS v4, React Flow, react-force-graph-3d (Three.js) |
| Backend | FastAPI, SQLAlchemy 2.0, Alembic, Pydantic v2 |
| Database | PostgreSQL 16 + pgvector (Supabase) |
| LLM | Groq (Llama 3.3 70B), local Ollama fallback |
| Embeddings | sentence-transformers, local, zero external dependency |

## Quick start

```bash
# Backend
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp ../.env.example .env   # set DATABASE_URL (Supabase) and GROQ_API_KEY
alembic upgrade head
uvicorn app.main:app --reload --port 8000

# Frontend (separate terminal)
cd frontend
npm install
npm run dev   # http://localhost:5173
```

Seed the initial dataset:
```bash
python scripts/seed_research_sources.py
python scripts/seed_processes.py
```

Or trigger the same pipeline live, right now:
```bash
python scripts/bootstrap_minimal_data.py   # prints a value_chain_id
curl -X POST http://localhost:8000/api/processes/analyze \
  -H "Content-Type: application/json" \
  -d '{"process_name": "Warehouse Inventory Forecasting", "value_chain_id": "<paste>"}'
```

## Testing

```bash
DATABASE_URL="postgresql+psycopg://postgres:testpass@localhost:5432/aegisai_test" pytest tests/ -v
```

**94 backend tests, all run against a real PostgreSQL database** — no
mocks for anything database-shaped, since the schema depends on
Postgres-specific behavior (pgvector, native enums, UUID keys) that a
lighter-weight test double wouldn't catch. Coverage includes full
pipeline runs proving the deduplication mechanism works across repeated
analysis, deterministic scoring verified to exact numeric boundaries, and
API-level tests exercising the complete request/response cycle.

The suite refuses to run against anything but a local database — a
structural guard, not a convention, after a real incident during
development where a misdirected environment variable pointed the test
suite's teardown at a live database. Full account, including the fix, in
the decision log.

## Engineering notes worth knowing

- **The LLM/code boundary is enforced by schema, not convention.** The
  extraction contract (`app/schemas/extraction.py`) only allows the model
  to propose factor estimates and reasoning — never a final score, trend,
  or match decision. Cross-reference validation rejects any response
  where the model references a role or skill that doesn't exist elsewhere
  in its own output.
- **Entity resolution runs through pgvector, not application memory.**
  Deduplication queries the database directly via indexed cosine
  similarity search rather than loading every existing role/skill into
  Python — the design that keeps this correct at 10 processes and at
  10,000.
- **Seed data and live analysis are the same code path.** The seed script
  calls the identical pipeline the API uses, with one flag distinguishing
  provenance. There is no separate, simpler mechanism that could silently
  drift from what a live judge's input actually exercises.

## Known limitations

- No natural-language query interface over the graph yet.
- No standalone research/evidence browsing page (evidence surfaces inline
  on AI opportunities instead).
- No automated frontend test suite — verified via TypeScript compilation,
  production build success, and manual browser testing.
- Development-mode deployment only; no single-command production build
  yet.
